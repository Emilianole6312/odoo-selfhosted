# ADR-004: Uso de código de barras único por producto
- Fecha: 31-07-2026
- Autores: Elevel
- Estado: Aceptado
- Supersedes: [ADR-003](https://github.com/Emilianole6312/odoo-selfhosted/blob/master/docs/adr/ADR-003.md#adr-003-manejo-de-productos-con-variantes-de-medida-con-script-automatizado-y-uso-de-uoms-de-odoo)

## Contexto

La decisión anterior (ADR-003) se basó en la suposición de que Odoo permitía 
asignar precios independientes a distintas UOM de un mismo producto y acceder 
a las diferentes presentaciones desde un único código de barras en el punto 
de venta.

Sin embargo, durante la implementación y tras revisar la documentación oficial 
de Odoo, se confirmó que esta funcionalidad **no es soportada nativamente**. 
Odoo vincula un producto a una UOM base y, aunque permite múltiples UOM 
de conversión, no permite precios independientes por UOM en POS.

## Decisión

Para cada presentación (UOM) de un producto se generará un código de barras 
único. Un script de migración separará los productos con múltiples UOM para 
su posterior procesamiento.

En el procesamiento:
- Algunos productos serán descartados
- Otros conservarán solo una presentación
- Otros requerirán generar códigos de barras adicionales para las presentaciones restantes

El punto de venta (POS) manejará estos como productos distintos, facilitando 
el escaneo y la venta independiente de cada presentación.

## Alternativas consideradas

- ** Módulo oficial de Odoo (Product UOM based Pricelist):** Aunque es una solución nativa de Odoo, conlleva costo de licencia adicional. Dado que los productos con múltiples presentaciones no representan una parte significativa del inventario, no justifica el gasto.

- **Módulo personalizado:** El desarrollo y pruebas de un módulo personalizado 
  requiere tiempo de desarrollo que retrasaría la implementación. Además, no es crítico para el sistema y existen alternativas completamente viables.

## Consecuencias
**Positivas:**
- Solución simple y sin dependencias adicionales

**Negativas:**
- El script de migración debe implementar lógica adicional para identificar y separar productos con múltiples presentaciones.
- Se requiere procesamiento manual para validar y ajustar los productos separados (precios, códigos de barras, descripciones).
- Los productos que originalmente tenían múltiples presentaciones aparecerán como productos independientes en reportes de inventario y ventas, sin relación explícita entre ellos. Esto complica trazabilidad y análisis al importar historiales de venta.
- Requiere documentación clara para el personal de ventas sobre qué productos son presentaciones del mismo artículo original.
