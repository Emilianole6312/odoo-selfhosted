# ADR-003: Manejo de productos con variantes de medida con script automatizado y uso de UOMs de odoo
Fecha: 29-06-2026
Autores: Elevel
Estado: Aceptado
## Contexto
Se requiere importar la totalidad de los productos del anterior punto de venta, esto incluye productos que tienen variantes de presentacion con precio para paquete y para pieza, odoo pv no es compatible con el formato que usa el PV anterior. 
Ademas los datos contienen distintos tipos de inconsistencia y segun las reglas del negocio, es necesario que tanto la presentacion en pieza como la presentacion en producto sean accesibles con un mismo codigo de barras.
## Decision
Adaptar el script para procesar los productos con variante y usar exclusivamente las UOM(unidad de medida): unidades y paquetes; para manejar las variantes de los mismos.
## Alternativas consideradas
Alternativa y Razón de descarte:
- Usar el modulo de variantes de odoo: Se considero usar este modulo para manejar las variantes de productos, pero se descarto pues las variantes son para productos con alguna variante no relacionada con la cantidad (ej. boing de mango, guayaba, uva, etc...).
- Descartar paquetes o piezas: Se considero descartar ya sea el paquete o la pieza dejando la decision en cada caso al usuario, pero en algunos productos son muy importantes las piezas tanto como los paquetes, por lo que se perderia informacion valiosa con esta solucion.
- Un script especializado para manejar estos casos: Se considero crear un script que no fuera completamente automatico y preguntara al usuario si queria conservar la solo la presentacion en pieza, en paquete o en su defecto ambas. Debido a inconsistencias en la forma de manejar las uom en distintas versiones de odoo se opto por descartar la solucion pues agregaba complejidad al problema al requerir crear uoms propias y no aportar un beneficio real frente a un procesamiento automatizado a corto plazo.
- Utilizar uoms propias con factores de conversion configurados para cada tipo de paquete: Finalmente se usaron excusivamente las uom: paquetes(creada manualmente) y unidades(default odoo); para evitar complicaciones de importar uoms personalizadas y evitar errores en la importacion de los productos.
## Consecuencias
- Todos los paquetes tienen un factor de conversión de 1.00 frente a la unidad, lo cual equivale a no tener conversion real entre estas UOM. Por lo tanto, la gestion de inventario o reportes basados en esta relacion no serán fiables. Sin embargo, dado que actualmente no existe un control de inventario, esto no representa una perdida de informacion real; estas UOM seran sustituidas por unas que reflejen la conversion real una vez se implemente dicho control. 
- Los errores en algunos productos persisten, entre ellos estan:
    - Productos con versiones de paquete y unidad identicas
    - Productos con version de unidad como paquete y version unidad con datos erroneos o antiguos.
    - Productos en los que solo interes conservar la unidad o el paquete.
    En consecuencia es necesario hacer una posterior revision de los datos junto con la busqueda de barcodes invalidos que duplican productos y barcodes no usados.
- El proceso de conversion es completamente automatico.
- Es necesario crear la uom paquetes dentro del grupo uom Unidad con un factor de conversion 1.00.
