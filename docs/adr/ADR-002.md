# ADR-002: Separación de productos con presentación múltiple y descarte de inventario anterior

Estado: Accepted
Fecha: 2026-06-04
Autores: Elevel

## Contexto

El sistema POS anterior exporta los datos en un formato incompatible con Odoo,
por lo que se desarrolló un script de migración (`migration/importarodoo.py`)
para transformar el catálogo al formato de importación de Odoo 17.

Durante el análisis del catálogo se identificaron dos problemas:

1. El inventario existente es mayormente negativo y no refleja existencias
   reales, por lo que no es confiable como punto de partida.
2. Parte del catálogo tiene productos con precio doble (`$24.00($6.00)`)
   que representan dos presentaciones (paquete y pieza) del mismo artículo,
   lo cual requiere configuración de variantes o UoM en Odoo que no puede
   automatizarse de forma segura en la migración inicial.

## Decisión

- Todos los productos se importan con tipo `consu` (consumible), sin
  seguimiento de inventario.
- El inventario del sistema anterior se descarta completamente.
- Los productos con precio doble se separan en un CSV aparte
  (`catalogo_variantes.csv`) para procesamiento manual posterior.

## Alternativas consideradas

**Conservar solo paquete o unidad para los productos con precio doble**
Descartado porque implica pérdida de datos de precios — o el precio por
pieza o el precio por paquete queda fuera del sistema.

**Importar con tipo `product` y ajuste de inventario inicial**
Descartado porque el inventario de origen no es confiable (mayoría de
existencias negativas) y generaría bloqueos en el POS al intentar vender
productos con stock en cero.

**Migrar variantes automáticamente**
Descartado porque el formato de variantes de Odoo requiere que los
atributos (`Presentación`) existan previamente en el sistema, y la
correspondencia entre presentaciones no es inferible de forma segura
desde los datos de origen.

## Consecuencias

**Positivas**
- El POS opera desde el primer día sin bloqueos por stock insuficiente.
- La migración del catálogo principal es mayormente automatizada.

**Negativas**
- Sin seguimiento de inventario hasta implementar un plan de migración
  gradual a tipo `product`.
- Los productos con presentación múltiple requieren configuración manual
  en Odoo antes de poder usarse en el POS.

## Artefactos relacionados

- `migration/importarodoo.py` — script de transformación
- `migration/catalogo_variantes.csv` — productos pendientes de configuración manual
